fbadmin 2.2.0 brings the work of milestones 2.2 to 2.5: operations (migrations, schema drift, replication setup, encrypted backups), insight and collaboration (notebooks, check-ups, the database timeline, links), automation (scheduled reports and check-ups, change requests, the continuous trace) and a fleet view. It also adds a **server edition** that installs fbadmin as a Windows service or a systemd service, and fixes every issue reported on GitHub so far.

Upgrade with `pip install -U firebird-admin`, use the Docker image or Helm chart, or download an installer below. Read **Behaviour changes** first: Disconnect now really disconnects, and fbadmin starts disconnected.

## Server edition for Windows Server and Linux ([#11](https://github.com/mariuz/fbadmin/issues/11))

- **`fbadmin-server-2.2.0-x64.msi`** installs fbadmin as the Windows service `fbadmin`.
  - It runs under a virtual account, `NT SERVICE\fbadmin`, so there is no password to manage.
  - It starts automatically and restarts after a failure.
  - Settings and data are in `C:\ProgramData\fbadmin`, kept on upgrade and on uninstall. Only SYSTEM, Administrators and the service can open them.
  - Silent install: `msiexec /i fbadmin-server-2.2.0-x64.msi /qn PORT=5050 HOST=0.0.0.0 FIREWALL=1`.
  - The update check is off: roll out new versions with your software distribution.
- **`fbadmin-server` deb and rpm** install a hardened systemd unit that runs as a dynamic user. Settings are in `/etc/fbadmin/fbadmin.toml` and data in `/var/lib/fbadmin`.
- **`fbadmin.toml`** sets any fbadmin setting in one file, for every kind of install. Environment variables and command-line options still win over it.
- **Rotated log file:** `--log-file` / `FBADMIN_LOG_FILE`. A service stop shuts fbadmin down cleanly, within `FBADMIN_SHUTDOWN_TIMEOUT` seconds.

See [Running as a service](https://mariuz.github.io/fbadmin/admin/service/), which also covers HTTPS through IIS (ARR) or Caddy.

## Behaviour changes

- **Disconnect really disconnects** ([#9](https://github.com/mariuz/fbadmin/issues/9)).
  - The server's or database's tabs close, its tree node collapses, and a password typed for this session is forgotten.
  - Nothing reconnects until you choose **Connect**. The dialog asks for the password unless it is saved.
  - **fbadmin starts with every server disconnected**, except *Local databases*.
  - Closing the last browser tab disconnects everything after 15 seconds (`FBADMIN_DISCONNECT_ON_CLOSE`; `0` turns this off). Reloading the page doesn't count as closing.
  - Only the browser UI is affected: schedules, alerts and the command line keep working. See [Security → Disconnect](https://mariuz.github.io/fbadmin/SECURITY/#disconnect).
- **Large uploads** (backups to restore, import files) are streamed to disk and no longer limited by `FBADMIN_MAX_REQUEST_BYTES` ([#10](https://github.com/mariuz/fbadmin/issues/10)). Limit them with `FBADMIN_MAX_UPLOAD_BYTES`; free space in the data directory is checked before and during an upload.
- The **All statements** trace template also logs each statement when it starts ([#1](https://github.com/mariuz/fbadmin/issues/1)). Firebird logs a SELECT's finish only when its cursor closes, so before this the trace looked one statement behind.

## Fixed issues

- Autocompletion quotes names only when needed, completes columns of an alias (`from artikel a` → `a.`), and replaces `$` names as a whole ([#2](https://github.com/mariuz/fbadmin/issues/2), [#7](https://github.com/mariuz/fbadmin/issues/7), [#8](https://github.com/mariuz/fbadmin/issues/8)).
- The Query Tool has **Fetch all** and *Rows: all*. Exports with rows still to fetch offer all rows, fetched first, or only the loaded ones, so they're never silently partial ([#5](https://github.com/mariuz/fbadmin/issues/5), [#6](https://github.com/mariuz/fbadmin/issues/6)).
- Tabs opened from the top bar scroll ([#4](https://github.com/mariuz/fbadmin/issues/4)).
- Disconnecting or dropping a database while a Query Tool fetch was running could crash the backend with the native client. A busy session is now cancelled and closed when it finishes.

## Operations (milestone 2.2)

- **Versioned migrations** from git or a directory: each database records what was applied, with a dry run on a copy ([Migrations](https://mariuz.github.io/fbadmin/MIGRATIONS/)).
- **Schema drift detection** against the schema history in git or against another database, on a schedule ([Schema drift](https://mariuz.github.io/fbadmin/SCHEMA_DRIFT/)).
- **Replication setup wizard:** sets up the primary and the replica end to end, including `replication.conf` and the first copy ([Replication](https://mariuz.github.io/fbadmin/REPLICATION/)).
- **Encrypted backups and restore drills:** AES-256-GCM while the backup streams in, with scheduled drills that prove a backup restores ([Backup encryption](https://mariuz.github.io/fbadmin/BACKUP_ENCRYPTION_DRILLS/)).
- **Query regressions:** statements grouped by shape with their runs and plans over time, flagged when they get slower or their plan changes ([Monitoring](https://mariuz.github.io/fbadmin/MONITORING/#query-regressions)).
- **Audit log forwarding** to syslog or signed webhooks, without losing entries; and the **Kubernetes operator** view of `FirebirdCluster`s ([Kubernetes](https://mariuz.github.io/fbadmin/KUBERNETES/)).

## Insight and collaboration (milestone 2.3)

- **SQL notebooks:** SQL and Markdown cells with results and charts, autosave and revision history ([Notebooks](https://mariuz.github.io/fbadmin/NOTEBOOKS/)).
- **Anonymised copies** of production with masking rules per column ([Anonymised copies](https://mariuz.github.io/fbadmin/ANONYMISED_COPIES/)).
- **Performance check-up ("why is it slow?"):** one ranked report from what fbadmin already collects ([Monitoring](https://mariuz.github.io/fbadmin/MONITORING/#performance-check-up)).
- **Database timeline:** DDL, migrations, backups, maintenance, alerts and more in one history per database ([Timeline](https://mariuz.github.io/fbadmin/TIMELINE/)).
- **Shareable links** to objects, saved queries, notebooks and result snapshots, opened with the viewer's own permissions ([Links](https://mariuz.github.io/fbadmin/SHAREABLE_LINKS/)).

## Automation and foresight (milestone 2.4)

- **Scheduled notebooks and reports**, run as the schedule's owner with their permissions.
- **Capacity and transaction-ID forecasts:** database growth, transaction numbers, sequences against their columns, and table formats, with warnings before a limit ([Monitoring](https://mariuz.github.io/fbadmin/MONITORING/#capacity-forecast)).
- **Scheduled check-up:** alerts only on what is new since the previous run.
- **Change requests with approval:** a developer proposes, an administrator dry-runs on a copy and approves, and fbadmin applies ([Change requests](https://mariuz.github.io/fbadmin/CHANGE_REQUESTS/)).
- **Continuous trace:** an optional always-on trace session per database that feeds the slow statement log and query regressions ([Monitoring](https://mariuz.github.io/fbadmin/MONITORING/#continuous-trace)).
- **Comments** on objects and notebooks ([Comments](https://mariuz.github.io/fbadmin/COMMENTS/)).

## Fleet view and follow-ups (milestone 2.5)

- **Fleet health page:** every database in one table, worst first, from fbadmin's own records ([Fleet](https://mariuz.github.io/fbadmin/FLEET/)).
- **Error log** from the continuous trace, with lock conflicts and constraint violations called out.
- **Unused index finder**, with the evidence and the DROP statements for a change request ([Monitoring](https://mariuz.github.io/fbadmin/MONITORING/#unused-indices)).
- **Weekly digest** per database to e-mail, Slack or webhooks.
- **Maintenance windows:** alerts are muted while a window is open, and approved changes can wait for the next one ([Maintenance](https://mariuz.github.io/fbadmin/MAINTENANCE/#maintenance-windows)).
- Propose a change request from the Query Tool. Other follow-ups: change requests, check-ups (with an AI inspection), forecasts as check-up findings, and continuous trace of procedures, functions and triggers.
