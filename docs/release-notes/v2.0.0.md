fbadmin 2.0.0 is the largest release since 1.0. It brings roadmap milestones 1.1, 1.2 and 2.0 and a phone and tablet layout, and fixes how several Firebird 4+ data types are read and written. Firebird 3.0, 4.0, 5.0 and the 6.0 snapshots are tested in CI. The interface is translated into all 8 languages.

Install or upgrade with `pip install -U firebird-admin`, use the Docker image or Helm chart, or download a desktop installer below. Read the [upgrade notes](#upgrade-notes) first if you run fbadmin in multi-user server mode.

## Highlights

### Alerts and backups (milestone 1.1)
- **Alerts** by email (SMTP), Slack-compatible webhooks (Slack, Mattermost, Rocket.Chat) or signed JSON webhooks.
  - Event rules: a scheduled job failed, a backup failed its test restore, online validation found errors, a cloud upload failed.
  - Condition rules, checked every minute: a large transaction gap (naming the attachment that holds the OAT), long-running transactions, replication lag, an unreachable database.
  - Cool-downs, "resolved" messages and a history of what was sent and delivered. See [Alerts](https://mariuz.github.io/fbadmin/ALERTS/).
- **Backup test restores:** a scheduled backup can be restored into a scratch database, opened and dropped again. Old backups are pruned, and a backup uploaded, only after it passes.
- **Cloud backup targets:** Amazon S3 and S3-compatible services (Cloudflare R2, Wasabi, MinIO, Backblaze B2), Azure Blob Storage and Google Cloud Storage.
  - Each schedule has its own folder and retention.
  - No cloud SDKs are needed, and secrets can be `env:NAME` references.

### Desktop and data tools (milestone 1.2)
- **Local databases in the desktop app:** open or create a `.fdb` file with the bundled Firebird 5 embedded engine, with no server. The Query Tool, backup/restore, validation and gstat all work on it. See [Local databases](https://mariuz.github.io/fbadmin/EMBEDDED/).
- **Data compare:** compares table rows of two databases by key, shows inserts, updates and deletes with sample rows, and downloads a sync script or applies it to the target in one transaction.
- **Event monitor:** register `POST_EVENT` names and watch them arrive live, with names suggested from your PSQL code.
- **Upgrade assistant:** checks a database before moving to Firebird 4, 5 or 6 and writes a migration plan.
  - It reports newly reserved words, legacy UDFs with their built-in replacements, dialect 1, authentication, time zones, external tables and schemas.
  - An optional trial restore on the newer server recompiles every view, procedure and trigger there and reports what fails.
- **PSQL debugging help:** trace a procedure, function or EXECUTE BLOCK step by step, with the line and variables after each statement. Everything is rolled back afterwards. On Firebird 5 you also get per-line profiler timings, and you can save test cases per routine.

### Teams and productivity (milestone 2.0)
- **Two-factor sign-in (TOTP)** with recovery codes. Admins can require it per user or for everyone.
- **API tokens** for scripts and automation: read-only or read-write, optionally limited to some servers.
- **Finer permissions:** grants per user or group, server, database and object pattern, at levels none / read / write / ddl / admin. Without grants, users keep the previous behaviour.
- **Shared query library** with folders, tags, search and revision history.
- **Multi-server overview:** one page with the health of every server and database.
- **Visual query builder:** tables, joins suggested from foreign keys, columns, aggregates, criteria and a live SQL preview.
- **Charts from query results:** bar, line, area, pie/donut and scatter charts, exportable as SVG or PNG.
- **ERD export** to SVG and PNG.
- **Schema history in git:** one file per object, committed on demand, after DDL or on a schedule. Includes diffs, objects at any commit, push to a remote and migration scripts between commits.
- **Command-line tool:** `fbadmin backup`, `restore`, `extract`, `diff`, `sql` and `check` for CI and cron jobs, with exit codes and `--json` output. Plain `fbadmin` still starts the web server. See [Command-line tool](https://mariuz.github.io/fbadmin/CLI/).

### Phones and tablets
- On phones:
  - fbadmin opens on the server overview;
  - the Object Explorer is a drawer and the toolbar a "⋯" menu;
  - a long press or "⋮" opens an object's actions;
  - dialogs are full-screen and controls are sized for touch.
- Tablets get a collapsible sidebar.
- fbadmin can be added to the home screen. There is deliberately no offline mode: stale server health would mislead.

## Fixes
- **Firebird 4+ data types:** the `firebirdsql` driver decoded INT128, NUMERIC/DECIMAL with more than 18 digits, DECFLOAT and time zone values wrongly. It also silently truncated large integer and decimal parameters to 64 bits, which could write wrong values.
  - fbadmin now patches all of these. Grid, Query Tool, exports and grid edits keep full precision and the time zone.
  - Details in [docs/upstream-firebirdsql-fb4-types.md](https://github.com/mariuz/fbadmin/blob/main/docs/upstream-firebirdsql-fb4-types.md).
- **Server mode:**
  - Scheduled jobs, monitoring history and alert condition checks now run as the user who set them up. Before, scheduled jobs failed with "Login required" and history tracking switched itself off.
- **Server overview:** no longer shows stale results after servers or databases are added or removed.
- **Smaller fixes:**
  - context menus could close a submenu right after opening it;
  - a race in the Query Tool could open two sessions;
  - the event monitor cleared names typed while another registration was running;
  - several missing accessible labels were added.

## Upgrade notes
- **Server mode: re-save schedules and re-enable history tracking.**
  - Existing schedules and databases tracked for monitoring history have no "run as" user yet. They report that the user who set them up is no longer available.
  - Open each schedule and save it, and switch history tracking off and on, as a user who should own them.
  - Creating or changing a schedule now needs the admin level on its database, and uploads to cloud targets are admin-only.
- **Back up `secret.key` with your data directory.** Server mode keeps `<data dir>/secret.key`, or uses `FBADMIN_SECRET_KEY` if set.
  - It encrypts two-factor secrets and the credentials scheduled jobs and alert checks run with.
  - Losing it means users must enrol 2FA again, and schedules, rules and tracking must be saved again.
- **Server-wide settings are admin-only in server mode:** the monitoring sampler and `/metrics`, and desktop updates.
- **API change:** TIME/TIMESTAMP WITH TIME ZONE values are returned as Firebird's own text, for example `2024-07-01 10:11:12.3456 America/New_York`, instead of an ISO string without the zone.
- **Desktop installers are larger** because they include the Firebird 5 embedded engine: about 7 MB more on Linux and 18–20 MB more on Windows and macOS (compressed).
- **Schema history needs the `git` command** on the fbadmin host.
- **The desktop builds are still not code-signed.** macOS Gatekeeper and Windows SmartScreen warn on first start; see [docs/PACKAGING.md](https://github.com/mariuz/fbadmin/blob/main/docs/PACKAGING.md#desktop-app).

## Known limitations
- **Firebird 6.0:** support is tested against the snapshots; final 6.0 support follows its release.
- **Cloud uploads:** tested against S3, Azure and GCS emulators (SeaweedFS, Azurite, fake-gcs-server), not real cloud accounts.
- **Schema-history push:** tested against a local remote only.
- **Small screens:** the ERD, query builder canvas and table designer work on phones but aren't comfortable there.
- **Command-line tool:** remote mode (running commands through a running fbadmin server with a token) is not implemented yet.
