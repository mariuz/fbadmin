# fbadmin 2.1.0 (unreleased)

> Draft: this section collects changes for the next release; it is finalised when 2.1.0 is tagged.

## Unreleased

### The native driver by default, with the pure-Python driver as backup and option

- **New default driver setting, *Automatic*:** fbadmin uses the native
  [`firebird-driver`](https://pypi.org/project/firebird-driver/) (on top of the Firebird client
  library) when it can, and the pure-Python `firebirdsql` driver otherwise. The native driver
  is much faster for anything that moves data, above all with wire encryption: BLOBs 25 to 380
  times, backup streaming 13 to 52 times, row fetches 3 to 5 times (see
  [Drivers](https://mariuz.github.io/fbadmin/DRIVERS/#benchmarks)).
  - *Automatic* picks native when `firebird-driver` is installed, a client library loads, it is
    a **Firebird 4 or newer** client (a Firebird 3 client would turn INT128, DECFLOAT and time
    zone values into legacy types) and it can load ICU (needed for time zone names).
    Otherwise it uses `firebirdsql` and says why.
  - The *Database driver…* panel shows the driver in use and the reason, and still offers
    *Native (firebird-driver)* and *Pure Python (firebirdsql)* explicitly. The log says which
    driver is in use at startup. `FBADMIN_DRIVER=auto|native|firebirdsql` works too.
  - **Safety net:** if a native connection fails because of the client library itself (it
    does not load, a plugin is missing), *Automatic* makes that connection with `firebirdsql`
    and reports it. Firebird errors such as a wrong password never trigger this.
- **`firebird-driver` is now a regular dependency** (Python 3.11+; it is pure Python on top of
  ctypes). `pip install "firebird-admin[native]"` keeps working; the extra is empty. The client
  library is not on PyPI: with a Firebird 4+ client installed (a Firebird 4/5 installation, or
  `libfbclient2` from Debian 13 or Ubuntu 25.04 and newer) fbadmin uses the native driver
  automatically; without one, or with a Firebird 3 client (Debian 12, Ubuntu 24.04), nothing
  changes: you get the pure-Python driver.
- **Docker image:** now includes the Firebird 5.0.4 client library for amd64 and arm64 (from
  the pinned, checksummed official release), with ICU, so it uses the native driver by
  default. `FBADMIN_DRIVER=firebirdsql` selects the pure-Python driver. The image is about
  19 MB larger compressed.
- **Desktop app:** *Automatic* uses the bundled Firebird 5 client for remote servers too.
- **ChaCha wire encryption for the native driver:** the bundled client file sets (desktop app,
  Docker image, `fetch-embedded.py`) now include Firebird's ChaCha plugin, so the native driver
  negotiates ChaCha64 with Firebird 4+ servers like a normal Firebird client, instead of Arc4.

### Upgrade notes

- If you had not chosen a driver, connections to Firebird servers now use the native driver
  when a Firebird 4+ client library is available (always in the Docker image and the desktop
  app). Results are the same (CI compares both drivers value by value); to keep the
  pure-Python driver, select *Pure Python (firebirdsql)* in *Database driver…* or set
  `FBADMIN_DRIVER=firebirdsql`.
- A saved explicit choice (`firebirdsql` or `native` in `driver.json`) is kept.

### Fixes
- **Native driver with an older client library:** with a Firebird 4 client library (for example
  Ubuntu 26.04's or Debian 13's `libfbclient2`) and a Firebird 5 server, backups, restores and
  sweeps no longer fail with "Invalid clumplet buffer structure". fbadmin offers only the
  service options both the client library and the server understand (parallel workers need a
  Firebird 5 client) and explains why. Server versions shown in the CLI's `check` and the
  upgrade assistant are unaffected.
