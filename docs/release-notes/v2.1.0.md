fbadmin 2.1.0 makes the native Firebird driver the default. Under a new *Automatic* setting, fbadmin uses `firebird-driver` on top of the Firebird client library when a suitable one is available, and the pure-Python `firebirdsql` driver otherwise, which remains a full alternative. The native driver is much faster for anything that moves data. Both drivers are tested side by side in CI on Firebird 3, 4, 5 and the 6.0 snapshot.

Upgrade with `pip install -U firebird-admin`, use the Docker image or Helm chart, or download a desktop installer below. See the [upgrade notes](#upgrade-notes).

## Highlights

### The native driver by default, the pure-Python driver as backup and option
- **New default driver setting, *Automatic*.**
  - It picks the native driver when `firebird-driver` is installed, a client library loads, the client is from **Firebird 4 or newer**, and ICU (used for time zone names) is available.
  - A Firebird 3 client would turn INT128, DECFLOAT and time zone values into legacy types, so Automatic doesn't use one.
  - Otherwise it uses `firebirdsql` and says why.
- **Choose explicitly** in *Database driver…* (user menu): *Automatic*, *Native (firebird-driver)* or *Pure Python (firebirdsql)*.
  - The panel shows the driver in use and why, which client library was found and its version, and whether ICU is available.
  - `FBADMIN_DRIVER=auto|native|firebirdsql` and `FBADMIN_FBCLIENT` override the setting.
  - The log names the driver in use at startup.
- **Safety net:** if a native connection fails because of the client library itself, *Automatic* makes that connection with `firebirdsql` and reports it. Examples: the library does not load, or a plugin is missing. Firebird errors such as a wrong password never trigger this.
- **Native covers every connection to a server:** the object explorer, Query Tool, create and drop database, and the Services API (backup, restore, gstat, validation, sweep, users, trace, log).
  - Per-server wire encryption, compression and authentication settings apply.
  - The event monitor keeps using `firebirdsql`.
- **Speed:**
  - BLOBs: 25 to 380 times faster.
  - Backup streaming: 13 to 52 times.
  - Small queries: 6 to 14 times.
  - Row fetches: 3 to 5 times.
  - Metadata loading: 1.6 to 3.3 times.

  Most of the difference comes from wire encryption, which `firebirdsql` does in Python. Method, caveats and full tables are in [Database drivers](https://mariuz.github.io/fbadmin/DRIVERS/), and `scripts/driver-compare.py` reproduces them.

### Where the native driver is used
- **Desktop app:** always. Automatic uses the bundled Firebird 5 client for remote servers too.
- **Docker image:** always. The image now includes the Firebird 5.0.4 client library and ICU for amd64 and arm64, from the pinned, checksummed official release.
- **pip:** when a Firebird 4 or newer client is installed:
  - a Firebird 4 or 5 installation;
  - `libfbclient2` from Debian 13 or Ubuntu 25.04 and newer.

  `firebird-driver` is now a regular dependency (Python 3.11+). `pip install "firebird-admin[native]"` keeps working; the extra is now empty.
- **Everywhere else** (no client library, or a Firebird 3 client as in Debian 12 and Ubuntu 24.04): the pure-Python driver, as before.

### ChaCha wire encryption
The bundled client now includes Firebird's ChaCha plugin. With Firebird 4+ servers the native driver negotiates ChaCha64 like a normal Firebird client, instead of Arc4. This applies to the desktop app, the Docker image and `fetch-embedded.py`.

### Testing
- The whole backend suite and the browser tests run under both drivers in CI on Firebird 3, 4, 5 and the 6.0 snapshot.
- One more job runs the native driver with Ubuntu's own Firebird 4 client against a Firebird 5 server.
- A cross-driver test sends the same queries through both drivers and requires identical results. It covers INT128, DECFLOAT, NUMERIC(38), time zones, BLOBs and character sets.
- The CI checks found and fixed several differences in the native adapter: error message format, exception classes, CHAR padding, INT128 without scale, and a thread-safety crash when statements were freed.

## Fixes
- **Native driver with an older client library:** with a Firebird 4 client library, such as Ubuntu 26.04's or Debian 13's `libfbclient2`, and a Firebird 5 server, backups, restores and sweeps failed with "Invalid clumplet buffer structure".
  - fbadmin now offers only the service options both the client library and the server understand, and explains why; for example, parallel workers need a Firebird 5 client.
  - Server versions shown by the CLI's `check` and the upgrade assistant are unaffected.
- **Long-lived metadata connections:** on Firebird 5, a connection that ran the same catalog query more than 1000 times failed with "Too many concurrent executions of the same request", because cursors were never closed.
- **Local databases:** when another Firebird client library had already been loaded in the process, they failed with "unavailable database". They now say so and ask for a restart.
- **firebird-driver 2.1:** supported. Its `get_client_version()` returns a tuple where 2.0 returned a number.

## Upgrade notes
- **Driver change:** if you had not chosen a driver, connections now use the native driver when a Firebird 4+ client library is available, which is always the case in the Docker image and the desktop app.
  - Results are the same: CI compares both drivers value by value.
  - To keep the pure-Python driver, select *Pure Python (firebirdsql)* in *Database driver…* or set `FBADMIN_DRIVER=firebirdsql`.
  - A saved explicit choice (`driver.json`) is kept.
- **Helm:** the chart's `driver` value now defaults to `auto`.
- **Docker image size:** about 19 MB larger compressed, mostly ICU.
- **Desktop builds:** still not code-signed.

## Known limitations
- **Not tested:** the arm64 Docker image was built in CI but has not been run. The ChaCha plugin was not tested on macOS and Windows.
- **Firebird 6:** on the 6.0 snapshot, `firebirdsql` misreads WIN1252 text BLOBs and parameters; the native driver handles them correctly.
